Frozen decisions: UDS-only production, three routes, base64 JSON control header and individually base64-encoded raw header values. Request body stays streamed. Local HTTP 200 distinguishes upstream statuses from local transport errors; metadata reconstructs standard Go responses. A mandatory success trailer prevents cancellation/crash/truncation from becoming clean EOF. WS upstream 101 precedes local upgrade; failures reconstruct actual upstream response. HTTP/HTTPS CONNECT and SOCKS DNS modes are explicit, no ambient Rust proxy or silent fallback. Default native HTTP, explicit CA rustls, WS rustls; TLS insecure configuration fails explicitly. Existing HTTP policy and bounded body settings cross the contract without introducing a general TLS settings framework.

Go integration signatures fixed in README; public options contain only existing ProxyURL, Settings and API/Auth Purpose, with all inheritance centralized in service. Independent implementers must use the same metadata fields, limits, error phases and success marker. Existing channel/account/session and billing state remain in Go. HTTP pool identity excludes request credentials; WS never shared. Go and Rust redirect count zero; local and Rust replay count zero; uncertain business replay count zero. Explicit library retry disablement needs listener-count tests, including protocol errors.

Review attention: local chunked success trailers for empty-body upstream statuses; gorilla local upgrade rejection response restoration; environment proxy resolution per target; bounded 1024-byte WS rejection payload in metadata to avoid gorilla failed-handshake body truncation; full fork support for HTTPS and SOCKS WS proxies; decoded versus encoded header limits; Go duration overflow; configured body limits above 2GiB fail explicitly; platform capability refusal; UDS startup/shutdown inode ownership. Unsupported capabilities may not be silently advertised or ignored.

Validation performed: JSON generated from deterministic bound table and parsed locally; all declared limits have min-1/min/min+1 and max-1/max/max+1 input cases. These are inputs, not passed tests. Implementation must add observed behavior assertions and Docker integration evidence. No credentials or captured provider payloads used.


Revision for independent panel: health is /v1/health; explicit API/Auth purpose and fixed profile; every transport failure (including pre-send) disables business retries. Effective global/channel timeout, idle counts, shards and proxy precedence now has a source-based table. WS total timeout is always zero; existing session idle/write rules remain Go-owned. Separate request/response/error metadata caps and a bounded rejection-body wire avoid ambiguous overflow and gorilla 1024-byte behavior. WS has byte and message-count queue caps plus a process-wide reservation budget. Early upstream upload rejection preserves actual status. Structured scenarios carry action inputs and exact expected attempt/redirect/resource counts. JSON syntax validation proves only fixture readability, not transport behavior.

Approved compatibility boundaries: enabled mode explicitly refuses insecure TLS and formerly unbounded idle settings; >128MiB WS configuration is rejected for bounded memory. Pool-cap enforcement and actual caller behavior remain implementation tests, not claims made by the contract panel.
