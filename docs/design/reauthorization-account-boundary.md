# Re-authorize：本站验证与上游 MFA 的边界

Re-authorize 修改已保存的 Codex 渠道凭据，服务端要求
`channel.codex.credentials.write` 范围的本站安全证明。
`/api/user/2fa/status` 和 `/api/user/passkey` 查询当前本站用户，
不会查询 OpenAI 或 ChatGPT 账号的 MFA 设置。上游 JWT 的 `amr` 不能替代本站证明。

此前修复覆盖状态查询失败被当作“未启用”的情况，但未解决用户将两个账号的安全设置混淆时的提示问题。
本次线上只读核查发现管理员在本站的两个因子均未注册；因此不能将该提示描述为上游账号 MFA 识别失败。

现在两个因子明确未启用时显示本站安全设置说明与 `/profile` 新标签页入口，保留原页面草稿。
注册完成后关闭验证弹窗并重试，会重新读取状态。安全因子的注册仍须由账号持有人完成。
已注册 Passkey 但设备不支持时，显示设备能力说明，不要求重复注册。
服务端 proof 校验未修改，也不会因缺少因子执行受保护的操作。

验证：前端类型检查、涉及文件 lint、44 个测试文件 / 226 项测试、生产构建与 500 行扫描通过。
回归覆盖无本站因子的设置引导、受保护操作未执行、设置后重新读取状态、设备不支持 Passkey，以及原有状态接口失败回退。
七种语言均包含新增提示；同步时补齐了既有繁体中文缺项。
